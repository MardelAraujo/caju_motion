# Caju vs. Remotion

[Remotion](https://www.remotion.dev) pioneered "video as React code", and Caju Motion borrows many of its public ideas (`useFrame` ≈ `useCurrentFrame`, `Sequence`, `interpolate`, `spring`, `delayRender`). Caju is a **clean-room** implementation: no Remotion code is used or derived.

The two projects make different bets. This page sums them up as of October 2026 (Remotion v4.0.x); check Remotion's own docs for its current state.

| | Remotion | Caju Motion |
|---|---|---|
| License | Source-available; free for individuals and small teams (up to 3 people), paid company license above that | **MIT** for the framework, Studio and renderer. Only an optional future cloud service is commercial |
| Source of truth | React code (`<Composition>`) | A JSON document, `project.json`, generated by code **and** edited visually |
| Authoring | React-first; the Studio edits props declared with zod | Hybrid: `video.ts` (`defineProject`) for structure, Caju Studio for timing and polish, React components (`defineComponent`) where keyframes aren't enough |
| Visual timeline editing | Offered as separate paid products (Timeline / Editor Starter) | Built in and free: multi-track timeline, move/trim/split, text, colors, audio, component props |
| Code ↔ visual round trip | — | `caju build` regenerates code clips and **keeps Studio edits**; conflicts are reported, never silently overwritten |
| Animation runtime | `useCurrentFrame`, `Sequence`, `interpolate`, `spring`, … | `useFrame`, `Sequence`, `Fill`, `interpolate`, `spring` (analytic), `Easing`, `random(seed)`, `delayRender` |
| Local render | Mature: `renderMedia` / `renderStill`, many codecs | `caju render` / `caju still`: H.264, H.265, ProRes 422, VP9, GIF, PNG sequence |
| Cloud / distributed render | Lambda, Cloud Run | Not yet (planned, F4) |
| In-browser player | `@remotion/player` | Not yet (`@caju-motion/player`, F4) |
| Templates / scaffolding | `create-video` with many templates | `create-caju` with 5 templates (v0.2) |
| AI support | Agent skills, `llms.txt` | Agent skills (`caju skills add`), `llms.txt` |
| Maturity | Years in production, large ecosystem | Young (v0.2) |

## When to pick which

- **Pick Remotion** if you want a mature, React-only workflow with cloud rendering today and its license fits your team.
- **Pick Caju** if you want designers or editors to adjust what developers (or agents) generate — on a real timeline, without losing either side's work — under an MIT license.

Both are frame-based and deterministic, so ideas move between them easily.
